# Guided Implementation Plan

## Goal

スクラップを検索・閲覧・タグ編集・Git同期できるRustデスクトップアプリを、利用者が各作業単位を理解しながら実装する。左側でタグとスクラップ一覧を切り替え、右側の本文を維持する。

## Non-goals

本文編集、タグ一括統合、複数保管庫、スマートフォン、常時自動同期、アプリ内競合解決は対象外。本計画の作成時にはソースコードや実際のスクラップを変更しない。

## Current Context

- 設計の参照元: [スクラップビューアー全体設計案](20261002-1108-スクラップビューアー全体設計案.md)。各Stepの「設計 §N」は、この資料の節番号を指す。
- 作成日: 2026-10-02。ユーザーの「ある程度の作業単位」という指定に合わせ、16の機能単位に整理した。
- 現在はCargo.tomlに依存クレートがなく、src/main.rsは起動メッセージのみ。.plans/SPEC.mdは存在しない。
- 設定先は指定どおり `~/.config/scrap-viwer/config.toml`。プロジェクト名との表記差を勝手に補正しない。
- GUI候補はeframe + egui + egui_commonmark。互換バージョンと必須操作はStep 2までに検証し、合格前に採用確定としない。
- 設計資料の「案」は未確定事項。計画の保存は、GUIや保存方式などの未検証事項に合格したことを意味しない。

### 進め方

各Stepは機能上の区切りであり、一度に実装する大きな差分ではない。開始時にその単位の関連設計を読み、通常1〜2ファイル・50行未満の小変更に分ける。以下の行数は単位全体の概算で、テスト・依存ロックファイル・検証資料は別途増えることがある。新規モジュールの登録や依存追加も小変更に分ける。

利用者が実装し、アシスタントは説明・レビュー・確認を支援する。各単位の終了時に停止し、利用者の確認を待つ。後続単位へ自律的に進まない。実装はガイド付き実装スキルを使う新しいセッションで、下記Step番号と設計資料を参照して開始する。

## Step 15: 外部変更の検知

- Objective: 外部での文書変更を自動的に一覧と本文へ反映できる。
- Depends on: Step 14
- Why: エージェントやIDEの保存を手動更新なしでも把握する。
- Files likely touched: src/catalog.rs、src/app.rs、Cargo.toml。
- User implementation instruction: 設計 §11を参照し、監視イベント、連続イベントの集約、世代付き再読み込みを順に追加する。タグ編集中は下書きを保持して外部変更を通知する。同期中の更新要求は処理終了後に集約する。
- Expected diff size: 100–180 lines（小変更に分割）。
- Check: 外部で追加・置き換え保存・削除・連続更新を実行し、アプリ自身の保存と同期後にも確認。
- Acceptance criteria: 古い結果で状態が戻らず、再読み込みのループが起きない。監視失敗時も手動更新できる。
- Review focus: 編集中の下書き保護、選択文書の削除、Git処理と監視イベントの競合。
- Stop condition: この単位の確認結果と差分をレビューし、停止してユーザー確認を待つ。次の単位へ自動で進まない。

## Step 16: 日常運用の通し確認

- Objective: 初期版の操作と制限を確認し、使い始めるための説明を残す。
- Depends on: Step 15
- Why: 個々の成功が実際の利用の流れでも成立するか確認する。
- Files likely touched: README.md、.plans/運用確認結果.md（不具合の修正先は確認後に決定）。
- User implementation instruction: 設計 §12を参照し、起動→検索→タグ切り替え→相対リンク→タグ保存→同期→外部更新を一巡する。設定例と既知の制限、競合復帰を説明する。不具合があれば該当単位に戻って小さく修正する。
- Expected diff size: 50–120 lines（資料中心。修正は別差分）。
- Check: cargo check、既存の意味あるテスト、実機でコピー・IME・長文・操作遅延の確認。Gitは引き続きテスト用リポジトリを使う。
- Acceptance criteria: 設計の必須条件に合格し、未解決事項と計測条件・結果を記録している。
- Review focus: 未検証項目を合格としないこと、設定例と実装の整合、データ保存・同期の説明。
- Stop condition: この単位の確認結果と差分をレビューし、停止してユーザー確認を待つ。次の単位へ自動で進まない。
