# Guided Implementation Plan

## Goal

既存の段階計画の1～3を実施する。GUIを起動し、日本語・Markdown表示・範囲選択とコピーの操作を検証したうえで、指定のTOML設定を読み込める状態にする。

利用者が小さな変更を実装し、アシスタントが説明・レビュー・確認を支援する。

## Non-goals

- スクラップフォルダの探索、文書解析、検索、タグ編集、Git操作。
- 本番の一覧・本文画面の完成。
- 実際のホームディレクトリへの設定ファイル作成。
- GUI検証不合格時の代替表示方式の実装。必要になった時点で別途計画する。

## 実機検証で判明した表示方式の問題（2026-10-02）

- 検証構成：eframe・egui 0.36.2、egui_commonmark 0.25.0。Markdown本文は複数のeguiの表示部品として描画し、文字選択と部品をまたぐ選択を有効にした。
- 日本語表示は利用者が実機で確認した。これは選択・コピーの採用条件の合格を意味しない。
- Step 5の検証中、ドラッグで文字を選択したままホイールを回してもスクロールせず、画面下端へポインターを移動しても自動スクロールしなかった。
- 選択中のホイール移動量を取得して `ui.scroll_with_delta` へ渡す補助処理を試したところ、スクロールは可能になったが、ホイール操作で選択が解除された。画面外まで選択範囲を延ばせず、全文を選択できないと利用者から報告された。
- 使用中のegui 0.36.2の実装を確認した。`src/containers/scroll_area.rs` では他の部品をドラッグ中に通常のホイール処理を抑制する。`src/text_selection/label_text_selection.rs` の `on_end_pass` では、その描画パスで選択の両端を確認できない場合に選択を解除する。後者は画面外へ出た選択端点も想定した処理であり、今回の症状と整合する。
- 判定：現在の表示構成では、必須条件「スクロールを伴う画面外までの選択と、整形済み本文のコピー」は不合格。スクロールだけを補っても選択状態を保持できず、表示・選択の仕組みに問題がある。egui全体や将来のバージョンで実現不能と断定するものではない。
- 進行状況：Step 5で停止し、GUI採用判断は保留。Step 6以降と段階3へ自動で進まない。他の検証項目は個別に結果が得られるまで未確認とする。
- 再検討候補：Tauriなどを用いたWebView方式。同じ検証文書で画面外までの選択・コピーを実機確認してから採用を判断する。Tauriへの移行は未決定であり、代替表示方式の検証・実装は別途計画する。
