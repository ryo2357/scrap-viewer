# Guided Implementation Plan

作成日: 2026-10-02  
状態: 計画保存済み・未実装  
対象: 全体設計案の実装手順1「Tauriの最小構成」

## Goal

全体設計案の手順1「Tauriの最小構成」を実装する。WindowsでTauri＋Svelte＋TypeScript＋daisyUIの画面が開き、画面からRustの処理を呼び出して日本語の結果を表示できる状態にする。

参照設計: [スクラップビューアー全体設計案](20261002-1408-スクラップビューアー全体設計案.md)

## Non-goals

Markdown表示、設定読み込み、文書収集、検索、タグ編集、Git同期、配布用インストーラーは実装しない。

## Current Context

- ルートのCargo構成はRust 2024 editionで、依存は未追加。
- `src/main.rs` は起動メッセージだけ。
- `.plans/SPEC.md` は存在しない。
- Rust 1.98.1、Cargo 1.98.1、Node.js 24.19.0を確認。`pnpm` の利用可否・バージョンは未確認で、所在・PATHの確認が必要。
- 作業ツリーには既存の変更・削除がある。初期化時に上書きや復元をしない。
- 標準配置として、フロントエンドを `src/`、Rustアプリを `src-tauri/` に置く。ルートCargo workspaceは設けず、Rustの確認には `--manifest-path src-tauri/Cargo.toml` を使う。
- Tauri 2＋Svelte＋TypeScript＋Vite＋Tailwind CSS＋daisyUIを使用し、SvelteKitは導入しない。
- pnpmを使用する。具体的な依存バージョンは実装時に互換性を確認し、フロントエンドは `pnpm-lock.yaml`、Rustは `Cargo.lock` で固定して記録する。
- この計画の完了後に、手順2の閲覧検証へ進む。
- 各ステップは人間が実装してレビューする単位とし、確認なしで後続ステップへ進まない。

## Step 1: Windows開発環境を確認する

- Objective: アプリ生成・ビルドに必要な環境を確認する。
- Depends on: None。
- Why: 構成の問題と開発環境の不足を区別するため。
- Files likely touched: `README.md`。
- User implementation instruction: pnpmの所在・PATH、RustのMSVCターゲット、Visual Studio C++ Build Tools、WebView2を確認する。不足を解消し、利用するバージョンと起動手順を記録する。
- Expected diff size: 10–25 lines。
- Check: `rustc --version`、`rustup show`、`node --version`、`pnpm --version`、Windowsのインストール済み機能を確認する。
- Acceptance criteria: pnpmが実行でき、Windows用Tauriをビルドする前提が揃っている。
- Review focus: 重複インストールを避けること、実行するシェルからツールを利用できること。
- Stop condition: 環境確認結果をレビューし、停止してユーザー確認を待つ。

## Step 2: 標準テンプレートを取り込む

- Objective: Tauri＋Svelte＋TypeScriptの最小アプリを配置する。
- Depends on: Step 1。
- Why: 標準構成を起点にして、設定を一から組み立てる負担を減らすため。
- Files likely touched: `package.json`、`pnpm-lock.yaml`、Vite・TypeScript・Svelte設定、`index.html`、`src/`、`src-tauri/`、ルートの `Cargo.toml`・`Cargo.lock`、`.gitignore`。
- User implementation instruction: 作業用ディレクトリで公式テンプレートを生成し、パッケージマネージャーにpnpmを選び、必要なファイルを確認して取り込む。依存の導入は `pnpm install` を使い、Tauriの開発・ビルド用設定もpnpmのコマンドに合わせる。既存の空のRustアプリを標準配置へ移行し、重複するルートCargo構成を整理する。既存の計画・スクラップ・変更を保護する。
- Expected diff size: 生成コード数百行＋ロックファイル。初期構成生成のため、1〜2ファイル・50行未満の例外とする。
- Check: `pnpm run check`、`pnpm run build`、`cargo check --manifest-path src-tauri/Cargo.toml`、`pnpm exec tauri dev`。
- Acceptance criteria: Windowsでテンプレート画面が開き、開発用の再読み込みが動く。
- Review focus: SvelteKitが含まれないこと、Viteの出力先とTauri設定が一致すること、既存ファイルを上書きしていないこと。
- Stop condition: 生成物と起動結果をひとまとまりとしてレビューし、停止してユーザー確認を待つ。

## Step 3: Tailwind CSSとdaisyUIの依存を設定する

- Objective: ViteからTailwind CSSを処理できる状態にする。
- Depends on: Step 2。
- Why: 見た目の導入と画面の変更を分けて理解するため。
- Files likely touched: `package.json`、`vite.config.ts`。`pnpm-lock.yaml` は自動更新。
- User implementation instruction: 互換性を確認したTailwind CSS・Viteプラグイン・daisyUIを追加し、既存のSvelteプラグインを維持してViteへ設定する。
- Expected diff size: 10–25 lines＋ロックファイル。
- Check: `pnpm run check`、`pnpm run build`。
- Acceptance criteria: 依存解決とフロントエンドビルドが成功する。
- Review focus: 使用するメジャーバージョンに合う設定であること、不要なPostCSS設定や依存を追加しないこと。
- Stop condition: 依存と設定をレビューし、停止してユーザー確認を待つ。

## Step 4: 日本語の最小画面を作る

- Objective: daisyUIの標準スタイルが適用された日本語画面を表示する。
- Depends on: Step 3。
- Why: 標準部品の使い方と、日本語の表示・入力を確認するため。
- Files likely touched: `src/app.css`、`src/App.svelte`。CSS名はテンプレートに合わせる。
- User implementation instruction: CSSへTailwind CSSとdaisyUIを設定する。テンプレート画面を日本語タイトル・入力欄・ボタン・結果欄に置き換える。
- Expected diff size: 25–45 lines。
- Check: `pnpm run check`、`pnpm exec tauri dev`。日本語表示とIME入力を確認する。
- Acceptance criteria: 標準スタイルが適用され、入力欄で日本語を変換・確定できる。
- Review focus: 独自デザインを増やさないこと、テンプレートの不要なスタイルが残らないこと。
- Stop condition: 画面と入力結果をレビューし、停止してユーザー確認を待つ。

## Step 5: 画面からRustへ通信する

- Objective: 入力値をRustへ送り、返された日本語の結果を表示する。
- Depends on: Step 4。
- Why: 画面とRustの処理境界を、小さな往復通信で理解するため。
- Files likely touched: `src-tauri/src/lib.rs`、`src/App.svelte`。
- User implementation instruction: テンプレートの通信例を利用して、日本語の確認用応答を返すコマンドを登録する。ボタンから呼び出し、成功結果と失敗時の案内を表示する。
- Expected diff size: 25–45 lines。
- Check: `pnpm run check`、`cargo check --manifest-path src-tauri/Cargo.toml`、アプリ内で日本語を入力して送信する。
- Acceptance criteria: 日本語の入力がRustへ渡り、結果が文字化けせず画面へ戻る。
- Review focus: コマンド名・引数の一致、Promiseのエラー処理、ファイルやシェルを操作する汎用コマンドを作らないこと。
- Stop condition: 通信結果と差分をレビューし、停止してユーザー確認を待つ。

## Step 6: 権限とリリース起動を確認する

- Objective: 必要な権限だけを持つ最小アプリが、開発時とリリース時に起動する。
- Depends on: Step 5。
- Why: 開発サーバーがあるときだけ動く構成を避けるため。
- Files likely touched: `src-tauri/tauri.conf.json`、`src-tauri/capabilities/default.json`。
- User implementation instruction: テンプレート由来の不要なプラグイン・権限を整理し、ローカル画面と通信に必要なCSPを設定する。開発時のVite接続も確認する。
- Expected diff size: 15–35 lines。
- Check: `pnpm exec tauri dev`、`pnpm exec tauri build --no-bundle`。生成されたWindows実行ファイルで表示・入力・Rust通信を確認する。
- Acceptance criteria: 両方の起動方法で動き、広範なファイル・シェル・外部サイト向け権限がない。
- Review focus: capabilitiesだけで独自コマンドの入力検証を代替しないこと、CSPに不要なワイルドカードを使わないこと。
- Stop condition: 手順1の完了と制限をレビューし、停止してユーザー確認を待つ。手順2へ自動で進まない。
